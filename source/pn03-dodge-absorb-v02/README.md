# P.N.03 回避吸収 v0.2（サイドステップ無敵 ＋ エナジー吸収 ＋ 吸収エフェクト）

日本版 **GPNJ08** 用（北米版 GPNE08 は同じフォルダの `GPNE08-dodge-absorb-v02.patch.txt` と [README-US.md](README-US.md)）。サイドステップ中はモーション全体が無敵で、その間に無敵で消した敵の攻撃 1 発ごとにエナジーが **+100** 回復し、**オーブを取ったときと同じエフェクトと音**がヴァネッサに出る。

## 2026-10-06 の改訂: 1 発 1 回加算、X = 100

- 通常の弾は、当たり判定の途中で「問い合わせ」（`BltDmageSet` を確定フラグ 0 で呼ぶ）と「確定」（`BltHitCk` 側）の 2 回、無敵の分岐を通る。これまでの日本版は両方で加算していたので、X = 50 の設定で実際は 1 発 +100 だった。
- フック 3 が問い合わせを数えないようにし（`cmpwi r6,0`／`beqlr` の 2 命令を追加）、既定の X を 100 にした。通常弾 1 発の量は従来どおり +100。確定つきでフック 3 だけを通る攻撃（爆風・貫通・エフェクト由来）は 50 → 100 になる。
- 北米版も同じ数え方・同じ X。
- 改訂後、日本版・北米版ともユーザーがゲーム内で確認済み（2026-10-06、「手触り自体は悪くなかった」）。

## v0.1 からの変更

- 吸収のたびに、エナジーオーブ回収と同じ演出: SE `0x37` と `0x39`（`0x800C9414(0, id, 0, 0)`）、エフェクト グループ 0・ID 0x14 を親 = ヴァネッサで生成（アイテム更新 `0x800A7EE0` の回収処理と同じ引数: `0x8008EE44(player, 0, 0, record, owner, 0, 0, player, 0)`）。
- 同じフレームに複数発吸収しても演出は 1 回（フラグ bit5。切ると毎発）。
- 吸収ルーチンが関数を呼ぶので自前の 32 バイトのスタックフレームを切る（9 番目の引数と、呼び先の LR 保存場所）。
- マーカー `DGA2`。それ以外（無敵の維持、吸収の条件）は v0.1 と同じ。

## 設計（ユーザー、2026-10-01）

後半ステージでエナジーが無いまま通常攻撃でチクチク連戦するのが楽しくない。爽快感の源は ED で、Normal 以上はステージのオーブでしか回復できず節約を強いられる。だからプレイヤースキルで能動的に回収したい。棒立ちのグレイズは受け身でつまらない。回避で弾に当たりに行くのは能動的で、吸収量の調整で塩梅が取れる。ステップ中は無敵でよい（スパムして無敵でも敵は倒せないのでバランスは崩れない）。v0.1 の所感「普通に面白い」→ 吸収時にオーブの演出を。

## 仕組み

- 無敵カウンタ `+0x4E1`（毎フレーム 1 減る。非 0 なら「弾は当たって消えるがダメージもヒット反応も無し」）。元のゲームはサイドステップ開始時に 3 を書く。
- **フック 1**（毎フレーム、プレイヤー更新 `0x800AFE80`。加速走り → 軌跡色 → 本パッチ → 偏差射撃の順に連鎖）: サブ状態 2（サイドステップ）の間、カウンタが 2 未満なら 2 にする。ステップ開始の検出、1 ステップの吸収数リセット、プレイヤーのポインタとフレーム番号の記録。
- **フック 2**（弾の当たりの確定 `0x8000B950`）／**フック 3**（`BltDmageSet` の無敵分岐 `0x8000C218`。確定の呼び出しだけを数える。爆風・貫通・エフェクト由来の攻撃はここだけを通る）: 対象が無敵のとき、元どおりダメージを捨てた上で、対象がプレイヤーかつサイドステップ中なら吸収: エナジー `root+0x6734` += X（上限 `root+0x6736`）、ゲージ更新 `0x80095CCC(0x80191BA0)`、演出。
- 基準: 小オーブ +250、安いドライブ 250、上限 1000〜2250（スーツ別）。

## 設定（Dolphin のメモリビューで即反映。セーブステートに含まれる）

## 検証

- Unicorn 2.1.4 で 41 ケース通過。v0.1 の項目に加え、吸収時の呼出し列（ゲージ更新 → レコード取得 (0, 0x14) → owner → 生成 `(player, 0, 0, record, owner, 0, 0, player, スタック引数 0)` を自前フレーム上で → SE 0x37 → SE 0x39）、同一フレーム 2 発目は演出なし、翌フレームは再び、フラグ bit3／bit4／bit5 と SE 0、レコード取得失敗時は生成せず SE のみ、スタック復元、非揮発レジスタ・LR 不変。加速中のセーブステートの実 RAM 上で実エフェクトシステム（レコード表・owner・生成器プール）を使って通し: 生成器が 1 個増え、レコードが (0, 0x14)、親がヴァネッサであることを確認。
- 2026-10-06 の改訂ぶん: 問い合わせ（確定フラグ 0）では加算も記録もせず呼び元へ戻ること、通常弾はフック 2 で 1 回だけ、確定つきの攻撃はフック 3 で 1 回だけ加算すること。配備 INI を丸ごと当てた統合テスト（`test_ini_chain.py`。改訂前の INI はこのテストで落ちる）と、セーブステートの実 RAM 上でゲーム本物の当たり判定を再生する検証（改訂前は 1 発につき吸収 2 回、改訂後は 1 回・+100）も通過。
- 改訂後の Dolphin 実行はユーザーが日本版・北米版の両方で確認済み（2026-10-06）。爆風を吸ったときの量（50 → 100）についての個別の所感は未報告。
